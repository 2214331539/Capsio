- **范围**：项目里“实验”模块的定位、界面结构、功能划分和分期。阅读、笔记、写作不在本文范围。

## 一、定位

**实验模块是一个面向科研的代码工作台。**

它首先是一个完整的本地开发环境：打开文件夹、编辑代码、终端、Python 环境、Git、Jupyter 笔记本。这些照 VS Code 和 PyCharm 的成熟做法来，研究生已经熟悉，不需要重新学。

在此之上，补上通用 IDE 没有、做实验又离不开的四样东西：

- **运行记录**：每次运行自动记下命令、代码版本（含当时未提交的改动）、参数、环境、日志和指标，可以比较、画曲线、用原代码重跑。
- **和研究打通**：运行结果、图表可以插入笔记和稿件；AI 能看到项目里的论文和笔记。
- **AI Agent**：在编辑器里就地改代码（先看差异再接受），排查失败的运行，总结一组结果。
- **团队同步**：代码、运行记录随项目同步给合作者。

**不按任务类型划页面。**数据分析、训练模型、画图都不是单独的功能页：分析数据用笔记本或脚本，训练就是运行一个脚本，画图是笔记本的输出或运行记录的图表。一个通用的工作台加上运行记录，就能覆盖这些任务。

## 三、用户和典型用例

主要用户是计算机、人工智能、数据科学方向的研究生，会用 Python 和 Git，平时用 VS Code、PyCharm 或 Jupyter。

| 用例                   | 用户怎么做                                                                                                                     | 用到的地方                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------- |
| 复现一篇论文的代码     | 克隆仓库 → 自动识别 environment.yml 或 requirements.txt，创建环境 → 按 README 选运行配置运行 → 结果自动成为一条运行记录        | 文件夹部件“克隆 Git 仓库”、状态栏的解释器、运行部件 |
| 接手自己已有的项目     | 打开本机的代码文件夹（原地使用，不复制）→ 选已有的解释器 → 继续写和跑                                                          | 文件夹部件“打开文件夹”、状态栏的解释器              |
| 写训练脚本、跑一组消融 | 编辑器写代码，Ctrl I 让 AI 改 → “以不同参数运行”给参数填多个值 → 面板“运行”看输出 → 运行记录里比较                             | 编辑器、运行部件、面板、运行记录                    |
| 探索数据、画图         | 打开 CSV 先看表格和分布 → 在笔记本里分析、画图 → 变量面板看中间结果                                                            | 数据查看器、笔记本、面板“变量”                      |
| 比较结果、出论文图     | 运行记录里筛选、勾选 → 比较（叠加曲线、参数差异、代码差异）→ 导出图或插入笔记、稿件                                            | 运行记录、比较                                      |
| 排查失败的运行         | 面板“运行”里的报错可以点到出错行 → 运行详情里“让 AI 排查” → AI 给出修改的差异 → 应用并重新运行                                 | 面板、运行详情、AI                                  |
| 管理代码版本           | 源代码管理里看改动、暂存、提交（AI 可以写提交消息）→ Git 图里看每个提交跑出了什么结果 → 新建分支，或在新文件夹中检出分支并行跑 | 源代码管理视图、Git 图、分支部件                    |
| 回到某个历史结果       | 打开那次运行 → “用原代码运行”：检出当时的提交和未提交的改动，在临时工作树里重跑                                                | 运行详情                                            |
| 和合作者协作           | 代码和运行记录随项目同步；运行表和 Git 图上显示是谁做的                                                                        | 项目同步（已有）、运行记录、Git 图                  |

一个项目可以有多个代码**文件夹**：自己的、克隆来的、某个分支的工作树。每个文件夹有自己的 Python 环境和运行记录，在顶部的文件夹部件里切换。原来的“实验”对象就对应这里的一个文件夹。

## 五、侧边视图

**资源管理器**

- 文件树，带 Git 状态（修改、新增、未跟踪）；`.venv`、输出目录这类被忽略的文件变灰。
- 新建文件、新建文件夹、刷新、全部折叠；下面有“大纲”。

**搜索**

- 在当前文件夹的文件里搜索和替换；区分大小写、全词匹配、正则表达式。

**源代码管理**（用语照 VS Code 中文版）

- 提交消息框（旁边的按钮让 AI 写），“提交”按钮；没有暂存时提交所有更改。
- 暂存的更改、更改两组；每个文件悬停出现打开文件、放弃更改、暂存。点文件打开差异。
- 最近的提交；有运行的提交带一个运行标记。
- 更多菜单：拉取、推送（后续）、储藏、合并分支、检出到。右上角打开 Git 图。

**运行**

- 运行配置：训练、评测、当前文件；悬停出现运行按钮。
- 正在运行：带进度；最近：带状态和主要指标。
- 打开全部运行记录。

**扩展**

- 留给后续的插件生态（例如包管理、远程计算、更多语言），现在显示“待开发”。

**Python 环境**（不占侧边视图，照 VS Code 的“选择解释器”）

- 状态栏右侧显示当前解释器，例如“3.11.9 ('.venv')”；点开是快速选择。
- 快速选择里：本机找到的解释器（venv、Conda、全局），输入解释器路径，创建虚拟环境（venv 或 Conda）。
- 文件夹里有 requirements.txt、pyproject.toml、environment.yml 时，同一处可以一键安装依赖。
- 创建或安装时状态栏显示“正在准备环境…”，新环境建好后自动选用。
- 单个包的安装、升级、卸载交给终端，将来由扩展提供管理界面。

## 六、顶部工具栏

- **文件夹部件**：显示当前文件夹；点开是快速选择：切换文件夹、打开文件夹、克隆 Git 仓库、新建空文件夹。
- **分支部件**：显示当前分支；点开可以检出分支、创建新分支、在新文件夹中检出分支（工作树）。已在别的文件夹检出的分支，选中后直接切到那个文件夹。
- **运行部件**：当前运行配置（下拉里切换配置、“以不同参数运行”、编辑配置）；运行（Ctrl+F5）、调试（F5）、停止。
- **更多**：新建终端、打开文件夹、克隆仓库、后台任务、在资源管理器中显示。

## 八、运行和运行记录

**什么算一次运行**：通过运行配置、“运行此文件”、“以不同参数运行”或 AI 启动的程序。终端里手动敲的命令不记录（和 VS Code、PyCharm 一致），需要时可以在运行记录里补登。

**自动记下什么**

- 命令、运行配置、工作目录；
- 代码版本：提交号，以及当时未提交的改动（保存成快照）；
- 解释器和已安装的包列表；
- 数据文件的位置和指纹（配置里声明的数据路径）；
- 日志、退出码、用时、发起人（我、AI、合作者）；
- 指标和产物（见下）。

**指标从哪里来**

- 程序写进运行目录的 `metrics.jsonl`，每行一条，例如 `{"step": 3, "loss": 0.42, "f1": 0.66}`；提供 `capsio.log(...)` 辅助函数，不装也能直接写文件。运行中实时更新曲线。
- 导入常见格式：PyTorch Lightning 的 CSV 日志、Hugging Face 的 `trainer_state.json`、TensorBoard 事件文件。
- 手动填写。只画真实记录的数值，不从日志里猜。

**运行记录编辑器**

- **表格**：状态、名称、参数列、指标列（每列最好的值加粗）、提交（有未提交改动时带星号）、发起人、开始时间、用时。可以按运行组、提交分组，或不分组；筛选；选择显示哪些列；导出 CSV。
- **图表**：每个记录了的指标一张曲线图，横轴是 step；上方选择显示哪些运行，颜色跟着运行走；下面是汇总表。
- **比较**：勾选 2–6 次运行后进入：叠加曲线、参数差异（只高亮不同的值）、指标对照；代码来自不同提交时可以直接看差异；可以让 AI 总结、插入到笔记。
- **以不同参数运行**：参数从入口文件的命令行参数读出；任何参数都可以填多个值，生成一组运行，合成一个运行组，按并发上限排队。

## 九、AI

- **内联修改**（Ctrl I）：选中代码或在光标处描述要改什么，差异直接显示在编辑器里，接受（Ctrl+Enter）才写入，可以撤消。
- **对话**（Ctrl J，右侧栏）：自动带上当前文件夹、打开的文件、选中的代码和最近的运行；修改文件时给出差异，可以“应用”或“应用并重新运行”。
- **排查**：运行失败时“让 AI 排查”，带上配置、环境摘要和出错位置附近的日志。
- **总结**：在比较页或运行记录里总结一组结果，可以直接开一组补充运行（例如补随机种子）。
- **提交消息**：源代码管理里根据改动生成。

## 十、快捷键

和 VS Code 保持一致：Ctrl P 转到文件、运行或命令；Ctrl Shift E 资源管理器；Ctrl Shift F 搜索；Ctrl Shift G 源代码管理；Ctrl Shift D 运行；Ctrl+F5 运行；F5 调试；Ctrl+` 终端；Ctrl I 内联修改。例外：Ctrl J 在 Capsio 里是打开 AI（VS Code 里是切换面板）。

## 十七、实验管理（第三版，未通过）

2026-11-15 评审：AI 味重；新建实验不该弹出一张通用表格，因为不同实验之间没有通用模板。应用里“实验”侧边视图先显示“待开发”，以后重新设计。下面保留第三版的思路作参考。

原型：[实验管理原型.html](../演示/实验管理原型.html)。2026-11-15 定：去掉“运行”这个概念，以**实验**作为管理单元；评审通过后，第八节和其他各节里的“运行”统一改成“实验”。

**概念**

| 概念       | 是什么                                                         | 例子                   |
| ---------- | -------------------------------------------------------------- | ---------------------- |
| 代码文件夹 | 代码在哪里，有自己的 Python 环境                               | timing、proagent-repro |
| 实验       | 一次带目的的执行：代码版本、参数、环境、日志、指标、产物、结论 | timing-abl-03          |
| 实验组     | 为同一个问题做的一组实验，例如扫参、消融、补随机种子           | 学习率扫描             |

**决定**

| 问题                 | 决定                                                                |
| -------------------- | ------------------------------------------------------------------- |
| 实验放在哪里         | 侧边视图“实验”（代替原来的“运行”）+ 实验页标签 + “全部实验”表格标签 |
| 一次执行算不算实验   | 算。▶ 直接开始的也是一个实验，目的和结论可以事后补写                |
| 实验必须属于实验组吗 | 不必须，没选就在“未分组”                                            |
| 一组实验怎么来       | 新建实验时参数勾选“多个值”，自动合成一个实验组，按并发上限排队      |
| 新建实验要不要建分支 | 不建；代码版本和当时未提交的更改由实验自动记下（快照）              |
| 和原来的第 2 期      | 合并：实验页、全部实验、比较、实验组就是新的第 2 期                 |

**实验页**：目的、指标和参数、曲线、结论（可以让 AI 起草、插入笔记）、怎么做的（配置、命令、代码版本、解释器、数据、时间）；日志、产物在子页签里。操作：停止、复制为新实验、用原代码重做、插入到笔记、收藏。

**和现有数据**：现在“运行记录”里手动新建的记录（实验方案、配置、结论）迁移为实验；已有的运行记录迁移为“未分组”的实验。
