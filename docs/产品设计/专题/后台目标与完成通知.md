# 后台目标与完成通知

整理日期：2026-11-23。负责人的要求：一轮对话结束后如果还有没做完的事（例如等训练跑完），AI 在后台等着，完成后接着做，并在应用内通知；切换项目时后台照常运行，前端只看到当前项目的对话。尽量用 Codex 已有的能力和开源项目的做法，不自己造。

## 现状

| 方面 | 现在 |
| --- | --- |
| 切换项目 | 不中断。AI 任务归应用管，每个项目的对话在右侧栏各自保留、互相看不见；切回来能看到后台做完的结果（`WorkspaceShell.test.tsx` 有测试） |
| 一轮结束之后 | AI 停下，不会再等后台任务，也不会回来通知 |
| 关闭应用 | 正在执行的一轮按“停止”保存，下次打开点“继续”（0.5.0-alpha.2） |
| 能长时间跑的东西 | 实验运行（独立进程，有日志和状态）、终端、装依赖、全文翻译队列、云主机 |
| 通知 | 应用内通知中心（新团队项目、同步问题、失败的运行），没有 AI 完成的通知 |

## 借鉴什么

| 来源 | 能力 | 我们怎么用 |
| --- | --- | --- |
| **Codex 目标（/goal）**，已转正 | 每个对话一个目标：目标内容、状态（进行中、暂停、受阻、额度用完、预算用完、完成）、token 预算、已用 token 和时间；**对话空闲、目标进行中且没超预算时，Codex 自己开始下一轮**；存在 Codex 的 SQLite 里，重启后还在 | 直接作为“后台继续”的引擎：不自己写循环、不自己算预算。接口 `thread/goal/set`、`thread/goal/get`、`thread/goal/clear`，变化时推送 `thread/goal/updated` |
| Codex 排队消息 | 一轮进行中发的消息排队，结束后自动发出（`thread/queue/changed`） | 运行中再交代事情不用等 |
| Codex shell 工具 | 模型能启动长时间命令、后台进程，用 `sleep` 等待再查看，等待时几乎不耗 token | 等训练、等下载用模型自己的办法，不另做“等待”工具 |
| **Paseo**（开源 Agent 管理器） | 常驻进程管理所有 Agent；Agent 默认“完成时通知”；输入框上方列出正在跑的后台任务（shell、监视器），每个带停止按钮 | 通知默认开；输入框上方显示目标状态条和停止 |

## 要做的（只做衔接和界面）

| 编号 | 内容 | 说明 |
| --- | --- | --- |
| 1 | 先验证 | 在 0.158 引擎上确认：设置目标后空闲时会自己开下一轮；自动开的一轮的事件能被现有会话读到（会话现在只认自己发起的那一轮，见 `agent-session.ts`） |
| 2 | 后台目标的入口 | 对话里一句话交代目标即可：AI 判断任务要长时间运行时调用 `thread/goal/set`；用户也可以在输入框菜单里“设为后台目标”。预算默认按套餐给一个上限，可改 |
| 3 | 不回收在跑目标的引擎 | 运行时会释放 60 秒没动静的引擎进程；目标进行中时不释放 |
| 4 | 显示自动开的轮次 | 会话跟上 Codex 自己开始的新一轮，消息照常出现在对话里 |
| 5 | 状态条 | 输入框上方显示“后台目标：进行中 · 已用 N 点 · 用时 M 分钟”，带暂停、停止；受阻或预算用完时说明原因 |
| 6 | 应用内完成通知 | 目标完成、受阻、预算用完，或者不在眼前的项目里一轮结束时：通知中心加一条（点开跳到那个项目的对话），对话列表和项目切换器上显示圆点。不做系统通知 |
| 7 | 关掉窗口时 | 有进行中的目标时，关窗口改为收到托盘继续运行，托盘菜单“退出”才真正退出（照旧中止并保存）；下次打开时 Codex 从 SQLite 读回目标，空闲后自动继续 |
| 8 | 权限 | 后台轮次沿用这个对话的权限档；遇到需要审批的操作，目标转为“受阻”并通知，不自己执行 |
